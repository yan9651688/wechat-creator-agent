# 公众号排版

## 用哪套

| 文章类型 | 排版 |
|----------|------|
| 教程、功能介绍、实操步骤 | `gzh-design` 的**红白色系**（`red-white`），简单干净 |
| 观点长文、专栏、需要更重视觉的单篇 | 从 `gzh-design/references/theme-index.md` 里挑别的主题，我点名时再用 |

我在请求里指定了主题，就按我说的；没指定就按上表。

`gzh-design` 技能放在 `.claude/skills/gzh-design/`，是 GitHub 上的开源排版技能（`isjiamu/gzh-design-skill`），可自行更新。红白风的全部组件在 `references/theme-red-white.md`，代码块、图片这些公共组件在 `references/common-components.md`。**HTML 一律从组件库里取，不凭记忆手写。**

## 红白风的几个要点

- 正文 15px、行高 1.8，全局容器最宽 677px。
- 每个正文段落挑 1 到 3 个关键短语，用淡粉下划线（`border-bottom:2px solid #FECACA`）。这是这套主题最主要的标记。
- 红色只用在锚点上：产品名、步骤、CTA、核心金句，全文不超过 5 处。
- `##` 用红底编号章节标题，`###` 用红色左竖条小标题。章节编号严格按顺序，结语章可以用 `∞`。
- 教程步骤用 `STEP 01` 标签组件，提示词和代码用代码块组件，不塞进普通段落。
- 开头引言卡的金句不复述标题，从正文里提一句有张力的判断。署名写你的名字（`红白配置.json` 的 `author`）。
- 文末签名区只有一个。原文末尾已经有落款句（`红白配置.json` 的 `signoff_prefix` 匹配到的那一段）就并进签名区，不再另生成一段。

## 排版不改稿

- 排版拿的是定稿（`2-定稿.md`），**不改字、不改标点、不改语序**。作者的怪标点、半角「-」、重复的字原样保留。
- 红白风要求正文全角标点。和定稿冲突时**以定稿为准**，校验脚本报的半角标点警告，如果是作者原文就在交付说明里列出来，不去改。
- 排完用 SHA-256 核对定稿文件没被动过。
- 哈希相同只说明源文件没变，还要对照输出中的文字、段落、图片与顺序。红白脚本支持没有 `##` 的文章，此时配置 `tags` 为 `[]`；不为适配排版硬加小标题或凑章节。
- 输出路径不能与源稿或配置相同（含软、硬链接）。配置不完整、章节与标签数不符、代码围栏未闭合时先处理错误，不覆盖旧成品。
- 一键复制总页的标题、摘要和正文使用同一份排版源稿。源稿在排版后又有修改，先重新排版再打包，不能拼接旧正文和新标题。
- 旧排版没有源稿版本标记时，总页兼容读取定稿（没有定稿才取自改稿），并提醒无法校验正文版本；重新排版后才能获得完整的版本核对。

## 产物

每篇放在 `文章/<日期>-<主题>/` 下：

| 文件 | 说明 |
|------|------|
| `<标题>_排版_红白色系(red-white).html` | 干净正文，纯 `<section>…</section>`，手动粘贴兜底 |
| `<标题>_排版_红白色系(red-white)_预览.html` | 带「复制到公众号」按钮，用 `wrap_preview.py` 生成 |
| `封面-公众号.png`、`封面-1比1.png` 等 | 2.35:1 封面同时放进正文首图（转 `封面-公众号.jpg` 内嵌，不加图注），公众号里「从正文选择」当封面；1:1 单独交付 |

## 图片

- 一键复制要把图带过去，正文里的图片必须是 `data:image/...;base64,...` 内嵌，不能留本地相对路径。常见的坑：「复制之后图片没带过去」的坑。
- 内嵌前把截图压到 1280 宽左右的 JPG，控制体积。
- `<img>` 用 `max-width:100%;height:auto;display:block;margin:0 auto`，不用 `width:100%`。
- 只有 `![说明](图)` 里真有说明才加图注，空 alt 不编。

## 校验（必须做）

```bash
python3 .claude/skills/gzh-design/scripts/validate_gzh_html.py <干净正文.html>
python3 .claude/skills/gzh-design/scripts/wrap_preview.py <干净正文.html>
```

ERROR 清零才算排完。然后在浏览器里打开预览页，看三件事：手机宽度（375px）没有横向溢出；图片数量和定稿里一样；点「复制」后剪贴板里的富文本包含全部图片。

没在公众号编辑器里实际粘贴过，就写「未在编辑器实测」，不说已经验证。

## 段落之间的配图

- 文字和文字之间要有搭配的图，大致每个小节至少一张，读起来不能是一大段字接一大段字。
- 一篇统一一种画风，跟文章主题走，不必是 IP 形象；IP 在正文里仍然最多一到两次（见 `03-形象与封面.md`）。
- 配图里不放文字。必须带字的（比如示例漫画的对白）逐字核对，错字用系统字体在原图上重写，原图保留。
- 真实截图、收益图、成品图优先，插画是补位，不拿插画冒充操作证据。
