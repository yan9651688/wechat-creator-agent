# 小红书

小红书版是从公众号文章拆出来的另一份东西：一套 3:4 竖图轮播，加几百字的短文案。读者先看到的是首图，划完图才看文案，所以图负责讲清楚，文案负责补一句我自己的话和留个口子。

这份规则还没有跑过一篇，跑完第一篇按实际情况改。

## 什么时候做、从哪来

- 默认从已经存好的 `2-定稿.md` 拆，事实只用定稿和 `素材与事实.md` 里有的。没有定稿就先问我拿哪一版拆。
- 公众号的定稿不改字，但小红书文案是重新写的短稿，不算定稿，要我确认过才算。
- 不是每篇都适合拆。教程、清单、对比、踩坑复盘拆起来顺；纯观点长文、产品发布公告先问一句要不要拆。
- 一样先问清楚走到哪一步停：只要文案、只要图、还是整套。

## 放在哪里

```
文章/<YYYY-MM-DD>-<主题>/小红书/
  文案.md        标题、正文、话题标签，我确认前是草稿
  分镜.json      每张卡片的底图和上面的字，叠字脚本照它渲染
  底图/          Codex 出的无字图
  卡片/          叠好字的成品，01.png 起按发布顺序编号
  提示词/        生图脚本自动写
```

## 一套图怎么排

- 6 到 9 张够用，不为了凑数加图。删掉一张读者不少理解什么，就删。
- **01 首图（封面）**：决定点不点进来，单独见下一节。
- **02**：这篇讲什么、给谁看。可以是一个问题、一个反常识的结果、一张对比。
- **中间几张**：一张只讲一件事，一个步骤、一个坑、一个对比、一个提示词。字多的时候宁可拆成两张。
- **最后一张**：收住，加一句行动话或者一个让人想回答的问题。不放二维码、公众号名、微信号。
- 实操类至少有一张真实截图或成品图，插画只解释流程，不当操作证据，这条和公众号一样。
- 整套用同一套版式：同一种底色、同一个标题位置、同一套字号，页码或进度放在同一个角。精美靠统一，不靠每张单独抽卡。

## 封面

默认做法：封面不一定要IP 形象，但一定要精美，一定要带爆款标题，在信息流里直接抓眼球。

- **标题是封面的主角**。先用 `baodian-title` 出几条候选，挑一条最抓人的做封面大字，给我看过再定。封面大字可以比笔记标题更短更冲，但两者说的是同一件事，数字要能在内页兑现，不放没核实过的收入和时间承诺。
- **字要大**：手机信息流里缩成很小一格还要一眼读出来。主标题最多两行，一行 8 个字左右；可以配一行小字副标题或标签（比如「亲测」「新手版」），亲测只在真测过时写。
- **画面服务标题**：可以是 IP 形象，也可以是成品截图、前后对比、一个有冲击力的物件或场景、纯排版大字。哪个最能让人看懂标题、想点进来就用哪个。
- **IP 默认当角标**：小红书读者还不认识你的形象，大画面让给标题和结果。形象固定放在同一个角、同样大小，作用是署名，读者翻主页时一排封面认得出是同一个人。用的话按 `03` 检查长相。
- **观点题 IP 可以当主角**：标题本身是情绪或冲突（「AI 写完先别发」这类），形象一个动作能把标题演出来，就让它占大画面。教程题、工具题交给大字和截图。
- **前几篇两种都发**，IP 主角和大字加截图各做几篇，看后台的封面点击率，哪种高就改这一条。现在这条是判断，还没有数据。
- **精美的标准**：主体清楚、对比强、留白干净，配色两三个颜色以内，字和画面不打架。不要廉价的大红大黄加描边、满屏贴纸、模板感很重的花字。
- **封面不必和内页一个版式**，但配色要接得上，划到第二张不像换了一篇。
- 每次出 2 到 3 版封面给我挑，不只交一版。

## 图怎么出

- **底图交给 Codex，字交给程序**。Codex 写中文字不稳，一套图张张有字，逐张抽卡改字太费。所以底图在提示词里写明「画面中不要出现任何文字」，并写清楚给文字留的空白区在哪（比如上方 40% 留空）。
- 底图照常用 `工具/生图.sh`，形象长相按 `03-形象与封面.md` 检查，那页的禁忌在这里全部适用。
- 尺寸统一 3:4，成品 1242×1660。生图时写「竖版 3:4」，出来比例不对就裁或重出，不拉伸。
- IP 不必每张都出现。封面看哪种画面最抓人；内页可以复用同一张底图换字，或者只放一个小头像当角标，省生图次数，也让整套更统一。
- 配色沿用两套：红白编辑风、暖黄手绘。一套图只用一套，不混。
- 叠字用 `python3 -I 工具/小红书卡片.py <小红书目录>`，读 `分镜.json`，用 Chrome 把每张卡渲染成 1242×1660，头像角标和页码自动加。内页底图默认用 `底图/内页纹理.png`。渲染完一样要逐张看、逐字核对。
- 不要 IP 的底图（物件封面、纸纹）用 `NO_IP=1 工具/生图.sh ……`，不带参考图。

## 文案怎么写

- **标题**：20 字以内（平台限制）。可以用 `baodian-title` 技能出候选，但数字要能在图和文案里兑现，不放没核实过的收入和时间承诺。
- **正文**：几百字就够，不超过平台 1000 字的上限。图里讲过的步骤不在文案里再抄一遍，文案说我自己为什么做这件事、踩到哪个坑、读者照做时最容易卡在哪。
- **口气还是我**，只是短。消息来路、口语垫句、同一个词反复说，这些照 `02-写稿与改稿.md` 来。短了也不要变成对仗金句。
- **不学小红书腔**：「家人们」「姐妹们」「绝绝子」「宝藏」「谁懂啊」、每句一个 emoji、满屏感叹号，都不要。emoji 最多当分段标记用几个，我确认风格前宁少勿多。
- 话题标签放在最后，3 到 6 个，跟内容真相关的，比如 `#公众号运营` `#AI工具` `#你的领域`。不蹭无关热点。
- 结尾留一个三秒能答上来的问题，让人愿意在评论区说一句。
- **默认不加落款**：公众号落款句不搬过来，正文以那个问题收尾，后面直接接话题标签。

## 平台上要注意的

- 正文和图里不放公众号名、外链、二维码、微信号，导流会被限流。我要在主页或评论里怎么引导，由我自己定。
- 需要评论互动或资料领取时，另写置顶评论草稿，说明留言什么、能收到什么和真实门槛；常见问题的回复只用 `素材与事实.md` 里的材料。评论草稿与正文分开，不把公众号落款或营销话术塞回正文，也不自动发送评论、私信或承诺领取效果。
- 图是 AI 生成的，发布时按平台提示勾选 AI 生成内容的声明。平台规则以我后台当时的提示为准。
- 发布、存草稿都停在我确认之前。只交文案和图，不替我登录、不替我点发布。

## 交付前检查

1. 封面缩到手机信息流大小，标题还一眼读得出来吗？放在一排别人的笔记中间，会不会先看它？用了 IP 的话，还认得出吗？
2. 每张图上的字逐字核对过了吗？有没有错字、乱码、水印、随机 logo？
3. 整套版式统一吗？底色、标题位置、字号、页码有没有跑？
4. 每个数字和产品能力，在定稿或 `素材与事实.md` 里找得到来路吗？
5. 有没有出现公众号名、外链、二维码？
6. 文案读起来还是我，没有变成小红书腔或者 ChatGPT 腔吗？
